## How We Tag

<!-- Wave-3B: fill in with git-cliff tag workflow + cliff.toml reference -->

Releases follow [Semantic Versioning](https://semver.org/): `vMAJOR.MINOR.PATCH`.

- `MAJOR` — breaking API or schema changes that require manual operator steps.
- `MINOR` — new features; existing deployments can upgrade with `./update.sh`.
- `PATCH` — bug fixes and security patches only.

To cut a release:

```bash
# 1. Ensure all waves have merged and tests pass.
uv run pytest -x
npm --prefix frontend run test -- --run

# 2. Generate CHANGELOG from conventional commits (see cliff.toml).
git cliff --tag vX.Y.Z -o docs/CHANGELOG.md

# 3. Tag and push.
git tag -s vX.Y.Z -m "Release vX.Y.Z"
git push origin vX.Y.Z
```

## How CHANGELOG Is Generated

<!-- Wave-3B: document cliff.toml sections, commit type → CHANGELOG section mapping,
and the conventional-commit prefixes in use (feat, fix, docs, chore, perf, refactor). -->

`docs/CHANGELOG.md` is generated by [git-cliff](https://github.com/orhun/git-cliff)
reading conventional-commit messages. The `cliff.toml` configuration lives at the
repo root (added in Wave-3B).

Key sections in the generated changelog:

| Commit prefix | CHANGELOG section |
|---|---|
| `feat` | Features |
| `fix` | Bug Fixes |
| `docs` | Documentation |
| `perf` | Performance |
| `refactor` | Refactoring |
| `chore` | Chores |
| `security` / `fix(security)` | Security |

## Docker Image Versioning

<!-- Wave-3B: document image tag strategy (semver vs :latest), registry location,
and the docker-compose.yml override pattern for pinned versions. -->

Images are built from `docker-compose.yml`. `versions.env` is the source of truth
for pinned image versions; the compose file uses `${VAR:-fallback}` so committing
a new pin is the upgrade.

```bash
# Pin a new version (example)
echo "PAPER_INGESTION_IMAGE=paper_ingestion:0.1.0" >> versions.env
git add versions.env
git commit -m "chore(release): pin image versions for v0.1.0"
```

## Release Checklist

Before tagging a release:

- [ ] All waves for the milestone have merged to `master`.
- [ ] `uv run pytest -x` passes.
- [ ] `npm --prefix frontend run test -- --run` passes.
- [ ] `uv run ruff check services/ libs/ scripts/` is clean.
- [ ] `docs/CHANGELOG.md` generated and reviewed.
- [ ] `docs/known-residual-risks.md` updated with any newly accepted risks.
- [ ] Docker images built and smoke-tested against a fresh stack.
- [ ] Tag signed and pushed.

## Rollback

```bash
git checkout HEAD~1 -- versions.env && ./update.sh
```

Never auto-rollback; always review the diff first. For schema rollbacks, see
`db/migrations/README.md` — migrations are intentionally forward-only; rollback
requires a DB restore from backup.
